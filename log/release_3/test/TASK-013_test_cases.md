## 依赖组件与 API

### 后端 API

| API | 方法 | 说明 |
|-----|------|------|
| `GET /api/v1/workbenches` | GET | 工作台列表（分页，query: `page`, `page_size`, `search`） |
| `POST /api/v1/workbenches` | POST | 创建工作台 (body: `name`, `description`, `owner_type`, `owner_id`) |

## 二、搜索功能测试（3 项）

### TC-006: 搜索框输入实时过滤（debounce 300ms）

| 属性 | 内容 |
|------|------|
| **ID** | TC-006 |
| **优先级** | **P0 — CRITICAL** |
| **类别** | 列表页 / 搜索 |
| **关联验收标准** | 搜索实时过滤，300ms debounce |

**前置条件**：
- 列表中有 5 条工作台：名称包含 "实验A", "实验B", "测试C", "测试D", "生产E"
- 后端 `search` 参数正确返回过滤结果

**测试步骤**：
1. 在搜索框输入 "实验"
2. 等待 300ms debounce
3. 验证列表过滤
4. 继续输入 "实验B"
5. 验证进一步过滤

**预期结果**：
- ✅ 输入 "实验" → 300ms 后 API 调用 `list(search: "实验")`
- ✅ 列表只显示 "实验A" 和 "实验B"
- ✅ 输入变为 "实验B" → 仅显示 "实验B"
- ✅ 搜索期间卡片无闪烁（旧数据保留直到新结果返回）
- ✅ 搜索输入框显示 placeholder "搜索工作台..."
- ✅ 搜索图标 `Icons.search` (20px) 显示在输入框内
- ✅ 输入 300ms 内的连续输入只触发最后一次 API 调用

**失败判定**：
- ❌ 每次按键都触发 API 调用（无 debounce）
- ❌ 搜索结果未过滤
- ❌ 搜索时清空列表再重新加载（闪烁）
